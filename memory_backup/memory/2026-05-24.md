## 红牛服务器修复

### 背景
- 晓东说「红牛还不能用」——一开始我忘了红牛是什么（记忆里叫「新服务器」）
- 红牛 = 111.229.0.148（腾讯云国内，OpenCloudOS 9.4）
- 跑 Hermes Gateway + gpt-5.5 (Schyler中转)，连飞书

### 排查过程
1. SSH 上红牛，发现 Hermes 进程活着（PID 734380，01:24启动），但飞书用户发消息得到的是预设回复而非模型回复
2. 查 error.log 发现大量 `Empty response (no content or reasoning) — retry 3/3` — gpt-5.5 返回空内容
3. 查 agent.log 发现 title_generator 收到 HTML：`'<!doctype html>\n<html lang="zh-CN">'`
4. 直接 curl 测试 Schyler API：非流式 ✅ / 流式 ✅ / 长上下文 ✅ — API 本身好着
5. 问题根因：
   - **主因**：Schyler 中转间歇性返回空内容（00:47、01:27、05:44 都出现），不是红牛本身问题
   - **次要**：`config.yaml` 里 `model.base_url` 设为 `https://api.schyler.top`（缺 `/v1`），辅助请求（title生成）打到网站首页返回 HTML，而 `.env` 的 `OPENAI_BASE_URL` 是带 `/v1` 的，主请求正常
6. 修复：`model.base_url` 补上 `/v1` → `https://api.schyler.top/v1`
7. 重启后 systemd 自动拉起，飞书已重连

### 教训
- 红牛=上海Hermes服务器，名字记牢了
- 配置文件里 base_url 路径不一致（config.yaml 缺 /v1，.env 有）容易踩坑
