- 症状：`sendMessage ret=-2 prepare failed`、`TypeError: fetch failed`、`AbortError`；`getUpdates` 报 TCP timeout / ECONNREFUSED
- 实测对比（同一时段）：
  - 直连 `ilinkai.weixin.qq.com`：3/3 成功，0.10–0.13s
  - 走 Clash `127.0.0.1:7897`：2/3 超时，1 次成功

- 结论：
  - **与 macOS 系统代理开关无关**，网关是显式连 7897 或直连
  - 代理节点/进程重启是主要风险；直连反而更稳
  - Clash 已加规则 `DOMAIN-SUFFIX,weixin.qq.com,主代理`，并切到 rule 模式（备用）
- 当前处置：网关 `proxy.enabled=false`，走直连；微信通道恢复
- 排查顺序建议：先 `curl -4` 直连 vs `curl -x 7897` 各 3 次，再查 mihomo 是否重启，最后才动网关配置
