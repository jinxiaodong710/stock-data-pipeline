## 16:00 深挖：18 元的真正原因（不是"会话长"）

晓东质疑"不能看表面理由"，查日志后确认他对：

- 15:00–16:00 共 14 次请求，累计 **626 万 prompt token**，单次上下文 58–64 万
- 日志出现 6 次 `cache read dropped 580864 -> 4608`，原因：
  - `systemPrompt digest changed (sections: Skills)` — 技能清单每轮都变
  - `imageCleanup changed provider history` — 历史里的图片每轮被重写
- 时间对上：workshop-skills 目录 15:48 被改，`diagnose-api-usage-spikes/SKILL.md` 16:01:30 又被写一次（后台技能复盘在连续改文件）
- 后果：58 万 token 的前缀缓存全部作废，只有 4–5k 命中；缓存价 $0.0028/M vs 全价 $0.14/M，**差 50 倍**
- 叠加 14:00–18:00 DeepSeek 高峰双倍价 → 本该 0.1 元的一小时变成 18 元
- 另有 `historyRewrite: message 0 envelope.timestamp` 每轮改写首条消息，也破坏 append-only

结论：这是**缓存失效型成本爆炸**，不是单纯上下文大。新会话必须不带图片；根治要处理后台技能复盘频率。
